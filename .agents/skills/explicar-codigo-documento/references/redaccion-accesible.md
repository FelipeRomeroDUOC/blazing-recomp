# Reglas de redacción para estudiar sin perderse

Estas reglas existen para que el documento sea fácil de seguir en sesiones cortas, también para personas con dificultades de atención o que prefieren lenguaje directo y estructuras predecibles. Hacen mejor el documento para cualquier lector.

## Estructura

- **Secciones cortas.** Cada sección se puede leer de una sentada en pocos minutos. Si una sección crece, divídela.
- **Títulos descriptivos.** Prefiere "Bloque 2: recorrer la lista de palabras" a "Bloque 2".
- **Siempre la misma forma.** Cada bloque sigue el patrón: código → qué hace → por qué → resumen → Tu turno → pausa.
- **Puntos de parada claros.** Las pausas marcan dónde se puede dejar de leer sin perder el hilo.
- **Resumen de una frase** al final de cada bloque, para repasar sin releer.

## Lenguaje

- **Frases cortas.** Una idea por frase y, en lo posible, un tema por párrafo.
- **Literal y concreto.** Di exactamente lo que ocurre. Evita ironía, dobles sentidos y frases hechas ("esto es pan comido", "la clave es…", "entre bastidores").
- **Analogías con cuidado.** Úsalas solo si ayudan de verdad. Márcalas como analogía ("Analogía: una variable es como una caja con etiqueta") y aclara dónde deja de ser válida.
- **Mismo nombre para la misma cosa.** Si llamas "lista" a una lista, no la llames después "colección" ni "arreglo" sin explicarlo.
- **Definir antes de usar.** Nunca uses un término técnico antes de explicarlo. Si el término aparece de nuevo mucho después, recuérdalo entre paréntesis.
- **Instrucciones explícitas.** Di qué hacer ("Escribe con tus palabras qué hace este bloque") en lugar de dejarlo implícito.

## Código dentro del documento

- Cita solo el fragmento que se explica (idealmente menos de 15 líneas).
- Usa bloques de código con el lenguaje indicado.
- Si te refieres a una línea, indica su número o cítala. Evita "esta parte" o "lo de arriba".
- Nunca pegues el archivo completo; si el usuario lo necesita, ya lo tiene.

## Ayudas visuales

- **Tablas** para el mapa general y para el seguimiento de variables paso a paso.
- **Listas cortas** (máximo 5 elementos) para pasos o características.
- **Negrita** solo para términos clave o etiquetas fijas (Qué hace, Por qué, Tu turno). No la uses para decorar.
- Emojis solo como marcadores fijos y consistentes (⏱ para el tiempo, ☕ para la pausa). No añadir más de los de la plantilla.

## Preguntas "Tu turno"

- Se responden con lo que el bloque acaba de explicar.
- Piden explicar con palabras propias ("¿Qué crees que pasará con `total` después de la segunda vuelta? Explica por qué.").
- Evita preguntas con truco o que requieran conocimiento no presentado.
- Las respuestas van en la sección final, no justo debajo de la pregunta.

## Tono

- Cercano y respetuoso, sin condescendencia. Evita "es muy fácil" o "simplemente": lo que parece fácil a quien escribe puede no serlo para quien estudia.
- Reconocer lo difícil está bien ("Este es el bloque más largo; tómate tu tiempo").
